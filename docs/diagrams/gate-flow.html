Arazu — one pipeline, two halves

Target to verdict

Buttercup finds the bug and writes the patch. The gate decides whether to believe it. Everything left of the seam is the CRS we run unchanged; everything right of it is the acceptance layer. The two share no model, no prompt and no failure mode, and that is the point. Gate stages run in order and stop at the first failure, and every refusal names a reason from a fixed vocabulary.

The left half

Buttercup, run unchanged

Trail of Bits' AIxCC CRS, deployed as shipped: 18 subcharts on Kubernetes, coordinating over Redis queues, building targets through oss-fuzz's own helper.py inside a privileged dind daemon. It takes real input today, so every project already onboarded to upstream oss-fuzz is a valid target, over 1300 of them, with nothing prepared on our side.

Model choice is a LiteLLM routing change, not a rebuild, so the CRS cannot tell a local model from a frontier one. That is what makes the yield-versus-safety claim testable rather than asserted.

Mull is the planned addition on this side. Note the direction: Mull mutates the target and asks whether the project's suite notices, so survivors are a prior for where to fuzz. Arazu's make mutation-test mutates the gate's own checks and fails if one survives. Same word, opposite directions.

Why the seam exists

The engine cannot tell its own patches apart

Two runs of the same libpng challenge, same host, same input. Run 1 rediscovered libpng's own fix. Run 2 changed one line so the bound matched the array, which really does fix the overflow, but left the png_uint_16 element type in place, so the keyword scan reads two bytes at a time and no keyword parses at all.

Every earlier signal cleared it. The PoV stopped firing, so M1 credited it. ASan and UBSan were clean, so M3 passed it. 29 PoV variants and the full suite passed, and Buttercup's own check reported that all PoVs were fixed. Only replaying the falsifying class caught it, and that is M2.

Both ship as run1.patch and run2.patch under corpus/falsifying-class/libpng-iccp/. Two runs is not a rate: it says the failure mode is real and reachable at $5.50, not how often it happens.

The right half

Eleven reasons, and the line between them

Nothing here is a model's opinion. Each stage decides by executing the target under podman, inside a network namespace with only loopback up, behind an lsm/socket_connect and lsm/socket_sendmsg denial keyed on the namespace inode. The signing key is sealed under a TPM policy over PCR 23, so tampering after acceptance moves the measurement and refuses the signature rather than producing one over changed output.

A refusal names a reason from a fixed vocabulary, and the vocabulary splits. Seven reasons are determinations about the candidate. Four say the run could not prove anything and route an operator to the harness rather than to the patch. Keeping those apart is what stops the gate inventing a verdict it never earned.
